# Phase 07: Project Setup Screen

**Date:** 2025-07-17 | **Status:** Draft

**Based on:** Discussion about new project initialization flow

## Problem

When a user opens a new folder/workspace in VS Code that doesn't have a `.consilium/` directory yet, the extension shows either the `ConfigErrorScreen` (if CLI/models are missing) or the `WelcomeScreen`. But there's no explicit step to **scaffold the workspace** for Consilium — the `.consilium/` directory only gets created lazily when the first session starts. This means:

1. New users don't know their project needs initialization
2. There's no way to proactively set up `.consilium/sessions/` and `.consilium/agents/` directories
3. The `/init` command (which scans the project and generates `AGENTS.md`) can't be run until a session has already started
4. The `AGENT.md` vs `AGENTS.md` naming mismatch between extension and CLI persists

## Solution

Add a new `"uninitialized"` status to the app initialization flow, and a new `ProjectSetupScreen` component that gives the user the option to scaffold the workspace or skip.

### New Status Ordering

```
App.tsx flow (proposed):
  no-api-key → SetupScreen
  uninitialized → ProjectSetupScreen (NEW)
  no-models → ConfigErrorScreen
  cli-error → ConfigErrorScreen
  no-workspace → ConfigErrorScreen
  ready → WelcomeScreen / ChatArea
```

## Changes

### Change 1: Add `checkProjectSetup` handler

**File:** `src/handlers/session.ts`

Add a new handler that checks if `{workDir}/.consilium/` exists with the required subdirectories:

```typescript
export const checkProjectSetup: Handler = async (_, context) => {
  const workDir = context.requireWorkDir();
  const consiliumDir = path.join(workDir, '.consilium');
  const sessionsDir = path.join(consiliumDir, 'sessions');
  const agentsDir = path.join(consiliumDir, 'agents');

  const initialized =
    fs.existsSync(consiliumDir) &&
    fs.existsSync(sessionsDir) &&
    fs.existsSync(agentsDir);

  return { initialized };
};
```

### Change 2: Add `initializeProject` handler

**File:** `src/handlers/session.ts`

Add a handler that scaffolds the `.consilium/` directory structure:

```typescript
export const initializeProject: Handler = async (_, context) => {
  const workDir = context.requireWorkDir();
  const consiliumDir = path.join(workDir, '.consilium');

  // Create directory structure
  fs.mkdirSync(path.join(consiliumDir, 'sessions', 'think'), { recursive: true });
  fs.mkdirSync(path.join(consiliumDir, 'sessions', 'do'), { recursive: true });
  fs.mkdirSync(path.join(consiliumDir, 'sessions', 'regular'), { recursive: true });
  fs.mkdirSync(path.join(consiliumDir, 'agents'), { recursive: true });

  return { success: true };
};
```

### Change 5: Create `ProjectSetupScreen` component

**File:** `webview-ui/src/components/ProjectSetupScreen.tsx` (new)

Create a new component modeled after `ConfigErrorScreen.tsx`:

```tsx
import React, { useState } from 'react';
import { ConsiliumLogo } from './ConsiliumLogo';

interface Props {
  onSetupComplete: () => void;
}

export const ProjectSetupScreen: React.FC<Props> = ({ onSetupComplete }) => {
  const [initializing, setInitializing] = useState(false);

  const handleInitialize = async () => {
    setInitializing(true);
    try {
      const result = await bridge.initializeProject();
      if (result.success) {
        onSetupComplete();
      }
    } finally {
      setInitializing(false);
    }
  };

  const handleSkip = () => {
    // Store skip flag so it doesn't show again for this workspace
    settingsStore.projectSetupSkipped = true;
    onSetupComplete();
  };

  return (
    <div className="flex flex-col items-center justify-center h-full gap-4">
      <ConsiliumLogo className="w-16 h-16" />
      <h1 className="text-2xl font-bold">Project Setup</h1>
      <p className="text-muted-foreground max-w-md text-center">
        This workspace hasn't been initialized for Consilium yet.
        Initialize it to set up the project structure for sessions and agents.
      </p>
      <div className="flex gap-3 mt-4">
        <button
          className="btn btn-primary"
          onClick={handleInitialize}
          disabled={initializing}
        >
          {initializing ? "Initializing..." : "Initialize Project"}
        </button>
        <button
          className="btn btn-secondary"
          onClick={handleSkip}
        >
          Skip
        </button>
      </div>
    </div>
  );
};
```

## Edge Cases

| Case | Handling |
|------|----------|
| Existing project with `.consilium/` | `checkProjectSetup` returns `initialized: true`, status stays `"ready"` |
| User skips setup | `projectSetupSkipped` flag stored in settings, prevents re-showing on refresh |
| Initialization fails (disk full, permissions) | Return `{ success: false, error: "..." }`, show error toast |
| Workspace changes mid-init | Not a concern — init is synchronous and quick |
| `.consilium/` exists but empty/missing subdirs | `initialized: false` — scaffold will create missing dirs |
| User re-opens skipped workspace | Skip flag persists in settings — goes straight to "ready" |
