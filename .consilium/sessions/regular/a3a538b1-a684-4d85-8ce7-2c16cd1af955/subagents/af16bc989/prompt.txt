# Implementation Report — Align PhaseStatus Vocabulary Across Codebase

## Executive Summary

The plan phase status vocabulary had a mismatch between the Python `PhaseStatus` enum (`pending`, `under_review`, `approved`, `implemented`, `aborted`) and the `plan_editor` subagent prompt (`planning`, `ready`, `implemented`, `archived`, `superseded`). The code enum was aligned to match the prompt, which is the more descriptive and complete vocabulary. Additionally, the Think system prompt was updated to remove the "on every turn" plan check and to always use `plan_editor` subagent for plan operations.

## Problem

Two incompatible status vocabularies existed simultaneously:

| Code `PhaseStatus` enum | `plan_editor_role.md` prompt |
|--------------------------|------------------------------|
| `pending` | `planning` |
| `under_review` *(unused)* | — |
| `approved` | `ready` |
| `implemented` | `implemented` |
| `aborted` | *(missing)* |
| *(missing)* | `archived` |
| *(missing)* | `superseded` |

The `plan_editor` subagent's self-validation checklist (line 337) only accepted `planning`, `ready`, `implemented`, `archived`, `superseded` — any phase document with `pending` or `approved` would fail validation. The `/plan init` LLM prompt templates also wrote `pending`, which the subagent would then reject.

Additionally, the Think system prompt incorrectly stated "You have access to" plan files (the Think agent has no filesystem tools — only `spawn_subagent`), and instructed checking the plan on every turn regardless of context.

## Changes

### 1. `PhaseStatus` enum (`plan/models.py`)

```python
# Before:
class PhaseStatus(str, Enum):
    PENDING = "pending"
    UNDER_REVIEW = "under_review"
    APPROVED = "approved"
    IMPLEMENTED = "implemented"
    ABORTED = "aborted"

# After:
class PhaseStatus(str, Enum):
    PLANNING = "planning"
    READY = "ready"
    IMPLEMENTED = "implemented"
    ABORTED = "aborted"
    ARCHIVED = "archived"
    SUPERSEDED = "superseded"
```

### 4. Think system prompt (`prompts/think_system.md`)

**Before:**
```markdown
## Plan Directory Awareness

You have access to the project's plan tree at:
...
On every turn, check `plan/index.md` to understand the current phase...

When creating a new phase spec:
3. Update `plan/index.md` to register the new phase
```

**After:**
```markdown
## Plan Directory Awareness

The project's plan tree is at:
...
When working on planning tasks, use `spawn_subagent` with `subagent_type: plan_editor` to read...

When creating a new phase spec:
3. Use `spawn_subagent` with `subagent_type: plan_editor` to update `plan/index.md`...
```

Key fixes:
- "You have access" → "The project's plan tree is at" (Think has no filesystem access)
- "On every turn, check" → "When working on planning tasks, use `spawn_subagent` with `plan_editor`" (only check when relevant, always via subagent)
- Step 3 now explicitly uses `plan_editor` instead of being ambiguous
