# Implementation Report — Fix Think Slash Command `work_dir` Dispatch

## Executive Summary

The Think mode slash command dispatcher unconditionally passed `work_dir=self._history.work_dir` as a keyword argument to **every** slash command function. Only `slash_checkpoint` and `slash_load` accept a `work_dir` parameter; all other 14 commands (including `slash_compact` and `slash_plan_cmd`) raised `TypeError: unexpected keyword argument 'work_dir'`, making `/compact`, `/plan init`, `/history`, `/edit`, `/delete`, and all other Think slash commands fail.

## Problem

In `think/__init__.py` line 564, the slash command dispatcher was hardcoded to always pass `work_dir`:

```python
result = command.func(self._history, self._think_session, call.args, work_dir=self._history.work_dir)
```

This was added during Phase 09 when `work_dir` support was introduced for checkpoint/load commands, but the dispatch was not updated to only pass the parameter to functions that accept it.

## Root Cause

Phase 09 added `work_dir` to `_handle_slash_and_get_result()` without inspecting whether the target function accepts it. The old code called `command.func()` with a hardcoded keyword argument, which broke all commands that don't declare a `work_dir` parameter.

## Fix

Changed the dispatch to use `inspect.signature()` to check whether the target function accepts `work_dir` before passing it:

```python
import inspect
sig = inspect.signature(command.func)
kwargs = {}
if 'work_dir' in sig.parameters:
    kwargs['work_dir'] = self._history.work_dir
result = command.func(self._history, self._think_session, call.args, **kwargs)
```
